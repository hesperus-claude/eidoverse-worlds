# Contributing

How to change this repo. Building *in* a world is [AGENTS.md](AGENTS.md); the docs are mapped in
[docs/README.md](docs/README.md).

## The loop

- Run a scratch server, never one someone lives on: AGENTS.md "Dev loop".
- The gate is `bun test/gate/run.ts` (or `bun run test:protocol`); name suites to run only those. What it needs
  and how it reports: [docs/contributing/GATE-MANIFEST.md](docs/contributing/GATE-MANIFEST.md). A change ships with the suite that would catch
  it breaking; a new suite goes in `test/gate/suites.ts`, then paste `run.ts --manifest`'s output into GATE-MANIFEST's generated block (`--check-manifest` refuses drift).
- Run suites with `BUN_RUNTIME_TRANSPILER_CACHE_PATH=0` (`test:protocol` sets it): a cached transpile once hid a
  stale module.
- `hygiene` refuses patterns that broke the gate before; its baseline (`test/gate/hygiene-baseline.json`) only
  goes down, never `--write` it up.
- Suites run in lanes (`test/gate/suites.ts`): `CORE` runs first and stops the gate on a failure, `BROWSER` lists every
  suite that launches a Chromium, and everything else is main. A browser suite missing from `BROWSER` fails preflight.
- Every test-named file is in the gate or in `test/gate/ungated.json` with one line why it isn't yet (hygiene's
  `ungated` rows). That list only shrinks: gate or delete a file to take it off; don't add one to dodge a red.
- Names: `-probe` drives a headless Chromium, `-check` is a protocol conformance check (mostly `test/protocol/`), and
  `-test` is everything else. Older files don't all follow it; the gate decides a suite's lane by what it launches, not its name.
- A test lives under the subject it exercises: `test/protocol/` for a claim in `spec/` checked through a real
  sequencer, `test/client/` for the browser client's own code, and likewise `server/`, `shared/`, `mcpl/`. The six
  `test/protocol/*-probe.ts` are client probes that predate this rule.
- New vocabulary (a component, an agent tool) climbs a ladder: [COMPONENT-LADDER](docs/contributing/COMPONENT-LADDER.md),
  [TOOL-LADDER](docs/contributing/TOOL-LADDER.md).

## Where a file goes

A file's directory says who runs it.

| directory | run by |
|---|---|
| `client/` `server/` `shared/` `mcpl/` `scripting/` | the product: browser, sequencer, the shared fold, the agent door, the script kit |
| `defs/` | the server, as content an operator edits (data, not code) |
| `test/` | the gate: `gate/` (the runner), `protocol/`, `client/`, `server/`, `shared/`, `mcpl/`, `services/`, `water/` (tests by subject), `harness/`, `stubs/`, `fixtures/`, `labs/` (run by hand) |
| `tools/` | a person or the server, by hand: CLIs (`world.ts`, the translator), `assets/` (converters), `operator/` (a server's operator) |
| `services/` | a server, always on: the show bots (`captionbot/`, `voicebot/`, `chatbridge/`), each with its own `package.json` |
| `bench/` | a person measuring: benches and one-off measurements, never the gate |
| `deploy/` | the VPS: install and ops scripts |
| `spec/` | an implementer somewhere else: the CC0 contract, and only what they need |
| `docs/` | a reader |

Conformance vectors follow one rule: a vector that binds other implementations lives under `spec/` (CC0, listed in
`spec/NORMATIVE.md`); a vector that pins one package's output lives beside that package (AGPL). Today:
- `spec/conformance/`: the log, physics, ed25519, laws and trig vectors, beside the reference reader;
- `spec/kernel-vectors/<dir>/`: written by `test/protocol/kernel-check.ts --pin --vectors <dir>`;
- `shared/conformance/{motion,water}.json`: generated by `tools/vectors/motion.ts` and `tools/vectors/water.ts`
  (each takes `--check`; the gate runs both). **Unreal reads both** (its plugin's `Resources/Conformance`), so a
  change to either changes what the native port must reproduce;
- `mcpl/vectors/manifest-digest-vectors.json`: read by `test/mcpl/manifest-test.ts`.

A doc's directory says who it is for and whether it binds: `spec/` binds; `docs/reference/` describes what is
built; `docs/guide/` (using a world), `docs/operator/` (running a server) and `docs/contributing/` (changing this repo)
get something done; `docs/design/` argues for what isn't built; `docs/research/` holds the why behind built code; `docs/decisions/` and `docs/history/` are dated and
frozen: supersede them, don't edit them.

## Style

- A new source file (.ts, .js, .mjs) is named in lowercase words joined by hyphens (`relay-decision.ts`), not run together or with underscores.
  The underscore names already in the tree are listed in `test/gate/underscore-names.json`; that list only shrinks.
- Comments: one line, plus a pointer (a doc section, a suite, an issue) when there is more. The story goes in the
  commit message.
- New docs are UPPER-CASE.md and live in `docs/`, except the root five (README, AGENTS, CONTRIBUTING, DESIGN,
  THIRD-PARTY), a directory's own README, and docs/research/ notes (lower-case, named by subject).
- Every relative link and every repo path in a doc or a comment resolves (`test/gate/paths-check.ts`). A moved file
  updates its references in the same commit.
