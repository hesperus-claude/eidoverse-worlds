# #260: where v4 differs from main on purpose

Each row is a place where #260 deliberately behaves differently from main. Antra decides each one: **keep** v4's way, or **revert** to main's. (Mica 10-29: kept as a table, never settled quietly during cleanup.)

| # | What it is | On main | On v4 | Antra: keep v4 / revert |
|---|---|---|---|---|
| 1 | Who may upgrade an old world to a newer protocol | (no upgrade existed) | A server operator, or the world's owner (matched from main's account records, or an exact unique name). An ownerless world becomes the upgrader's. The old copy is kept in `backups/` as the undo. | |
| 2 | First-run setup link | Operators set by config only | With no operator configured, boot prints a one-time setup link on the server console; any signed-in account that opens it becomes the operator (Jupyter/Plex style). Config still works. | |
| 3 | Login cookie on requests | Accepted only with `Sec-Fetch-Site: same-origin` | Accepted unless the browser says the request came from another website (`cross-site`), so sibling subdomains and native clients keep their login while other sites still can't use it (web.dev Fetch Metadata, OWASP). | |
| 5 | Rate limits | Hardcoded in the server | Server-operator settings (`RATE`, fork limits; 0 = none); no founding quota. A kick removes someone now and they may rejoin at once, as in Discord and Minecraft (`/kick`); keeping someone out for a while is a timed ban, the conventional tool (Discord/Twitch timeouts, Minecraft tempbans). | |
| 6 | Swim float depth | Floats at 1.1 × stature, with a 17.5 cm jump where water deepens | One float depth (1.275 m), no jump. | |
| 6b | Step height | 0.55 m (the client alone judged walking) | 0.8 m for now. v4's server also checks walking, by sweeping the body's box along the stride, and at 0.55 m that sweep refuses an ordinary staircase (several treads fall inside one stride). A follow-up returns to 0.55 m once the check follows the ground under the stride. | |
| 7 | Ambient motes | Up to 3,000 motes, 60 m range, own colour, follow the camera | Carried into a dust effect with their count, range and colour; the particle limits become adjustable. They don't follow the camera until cameras are things you can select in build mode (as Resonite parents an emitter to the user's head). | |
| 8 | Emote file `_emotes.json` | Read from the asset library | Not read; the engine reads `_actionbar.json`, and the layout ships in our own assets repo. An emote is one kind of action, as in Second Life gestures and VRChat's Action Menu, where one slot can trigger an animation, a sound, a chat line or a command; a separate emotes-only file would special-case one kind. | |
| 9 | Uploading a script over HTTP | `POST /upload?as=script` | Removed: a script is now saved through the world's own `upload {text}` request, the same door every other world change uses. One door means one check of who may do it, one log of who did what, and undo for everything, instead of a side door that skips them. The old URL answers 415 and says where to send it. | |
| 10 | Build-mode nudge keys | Q/E turned, comma/period resized, R/F raised a selected thing | Retired so the keys can match other editors' tool keys (G move as in Blender, E rotate and R scale as in Maya, F frame); the tools do these moves with a drag, and the inspector takes exact values. | |
| 12 | `use` with any event name | Any word was accepted; its only listeners were a pendulum's push and the world's behaviours | A `use` must name an action the thing declares (Godot/Unity's declared actions). The pendulum push is restored. Behaviours carry over but don't run, so using a thing whose behaviour was carried says so and how to re-install it; builders declare actions with real handlers. (No `use` acts or behaviours appear in the sample production worlds.) | |
| 13 | Build mode on phones | Build mode on any pointer | Not offered on a phone for now: building needs precise pointing and room for panels, and supporting it on a cramped touch screen for very few users isn't worth it yet. Could return in a later PR if there's interest. | |
| 13b | VR controller buttons | Jump on either controller's A | Jump on the right A only and the left X toggles the mic, as in VRChat's Touch defaults. | |
| 14 | Native Unreal client (#248) | Joins main's wire directly | Joins a v4 world through a small local bridge that folds the log with the engine's own code. It switches on by itself when a v4 world refuses a direct join, so the same build still joins main servers directly. Every live client test passes on a real GPU. Offered as its own PR on `eidoverse-unreal`. Choose: merge that PR alongside #260, or merge #260 first and the client PR after. | |
| 15 | Lights from glowing models | A glowing model made a light by itself (main placed an invisible point light at the centre of each glowing part, up to 2 per model, from a pool of 8) | Glow is only glow; lights are light components (as in Godot/Unity/Unreal). Upgrades turn main's inferred lamps into real lights. | |
| 17 | Throw key | C sank *and* threw | Q throws, the same key as Minecraft's drop; C/Ctrl only sink. | |
| 18 | Ownerless worlds | Could exist | Every upgraded world ends with an owner. | |
